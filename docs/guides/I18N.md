# i18n — Internationalization Guide

**OmniRoute-Slim is English-only.** There is exactly one UI locale, one CLI
catalog and one docs tree. This guide documents that architecture: what is still
here, what the single locale implies, and what it would actually take to add a
second one.

Historically this fork's upstream shipped 43 locales, a machine-translation
pipeline, per-locale glossary gates and a mirrored `docs/i18n/<locale>/` tree
(~55 MB). All of it has been removed. If you are looking for
`npm run i18n:run`, `generate-multilang.mjs`, `validate_translation.py`,
`check-glossary-consistency.mjs` or `bin/cli/scripts/generate-locales.mjs`, they
are gone — see [What was removed](#what-was-removed).

## Source of truth

`config/i18n.json` declares the supported locales. It ships one:

```json
{
  "default": "en",
  "rtl": [],
  "locales": [{ "code": "en", "label": "EN", "name": "English", "flag": "🇺🇸" }]
}
```

`src/i18n/config.ts` is a thin typed adapter over that JSON — `LOCALES`,
`DEFAULT_LOCALE`, `LANGUAGES`, `RTL_LOCALES`, `LOCALE_COOKIE`. Never hand-maintain
a locale list anywhere else.

Because `rtl` is empty, nothing in the app renders right-to-left: the root layout
hard-codes `dir="ltr"` rather than testing `RTL_LOCALES` on every render.

## Runtime: dashboard UI

| Piece                                        | Role                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| `src/i18n/messages/en.json`                  | The one message catalog (next-intl / ICU).                                |
| `src/i18n/request.ts`                        | next-intl request config. Resolves `DEFAULT_LOCALE` and serves `en.json`. |
| `src/app/layout.tsx`                         | Wraps the tree in `NextIntlClientProvider`, sets `<html lang>`/`dir`.     |
| `src/shared/lib/persistLocale.ts`            | Writes the `NEXT_LOCALE` cookie + localStorage mirror.                    |
| `src/shared/components/LocaleAutoDetect.tsx` | First-visit browser-language detection.                                   |

Two properties are worth knowing because they are easy to regress:

- **The catalog is normalized once, at module load.** `request.ts` builds
  `NORMALIZED_EN_MESSAGES` at module scope. `normalizeComplianceEventTypes()`
  rewrites dotted `compliance.eventTypes` keys into a nested tree, and it used to
  run per request — re-walking the tree and re-spreading the whole catalog on
  every page render and every server action, always to the same result, because
  `en.json` is a static import. Keep it hoisted.
- **`layout.tsx` must not normalize again.** `getMessages()` already returns the
  normalized object from `request.ts`. A second `normalizeComplianceEventTypes()`
  call there is a guaranteed no-op that costs a full catalog copy per render.

`LocaleAutoDetect` still exists and still writes the cookie, but with a single
locale it can only ever detect `en`, and `request.ts` does not read the cookie —
so it is inert. It is kept (with its regression test) because it is the correct
place for the logic if a second locale is ever added.

There is no language switcher in the UI. The old `LanguageSelector` dropdown
offered exactly one entry and fetched a flag image from `flagcdn.com` on every
dashboard and docs page load; it was removed from both `Header.tsx` and the docs
layout.

## Runtime: CLI

`bin/cli/locales/en.json` is the only CLI catalog, and `bin/cli/i18n.mjs` is
written around that fact:

- `detectLocale()` still reads `--lang` → `OMNIROUTE_LANG` → `LC_ALL` →
  `LC_MESSAGES` → `LANG`, but **every value resolves to `en`**. There is no
  second catalog, so there is no cross-locale fallback chain.
- The catalog path is the fixed `locales/en.json` — no caller-supplied locale is
  ever interpolated into a filesystem path, so a hostile `--lang ../../etc/passwd`
  cannot traverse.
- A key missing from `en.json` returns the key itself (no crash).
- `omniroute config lang set <code>` validates against `config/i18n.json` and
  exits 1 for anything other than `en`, so it fails loudly rather than silently
  serving English.

```bash
omniroute config lang list     # lists the one supported locale (en)
omniroute config lang get      # show currently active locale (en)
omniroute config lang set en   # persists OMNIROUTE_LANG=en to ~/.omniroute/.env
```

`OMNIROUTE_LANG` is retained in `.env.example` for forward compatibility and
because `config lang set` writes it.

## Runtime: docs

`docs/` is English Markdown/MDX rendered by Fumadocs. `src/app/docs/[...slug]/page.tsx`
renders `page.data.body` directly — there is no locale to resolve and no
translated-markdown branch to pick.

The route used to call a `getDocsLocale()` that read `NEXT_LOCALE` through a
**synchronous** `cookies()` call. `cookies()` returns a Promise in Next 15, so
`.get()` on it never resolved a cookie; the surrounding `try/catch` swallowed the
failure and the function returned `DEFAULT_LOCALE` by accident on every request,
while still opting the route into dynamic rendering. Both it and the
`docs/i18n/<locale>/` fallback it fed are gone.

`src/lib/docsI18nPath.ts` (`resolveSafeI18nSectionDir`) is retained with its
path-traversal test suite: it is a pure function and the correct hardening to
reuse if a translated docs tree ever returns.

## Quality gates that remain

| Gate                                         | What it guards                                                                                                                                   |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `npm run check:cli-i18n`                     | Every `t()` key in `bin/cli/commands/` exists in `en.json`; `bin/cli/locales/` contains **only** `en.json`; no `__MISSING__:` sentinels survive. |
| `npm run i18n:check-ui-coverage`             | Key parity across shipped UI catalogs (vacuous at one locale, kept armed).                                                                       |
| `npm run i18n:check-value-drift`             | A rewritten English value leaving stale translations behind.                                                                                     |
| `npm run i18n:sync-ui`                       | Backfills absent keys, marking untranslated ones `__MISSING__:<en>`.                                                                             |
| `tests/unit/i18n-placeholder-parity.test.ts` | ICU placeholder sets match English; asserts the shipped set is exactly `["en"]`.                                                                 |
| `tests/unit/i18n-config.test.ts`             | `src/i18n/config.ts` reflects `config/i18n.json`.                                                                                                |

The placeholder-parity and `check-cli-i18n` gates deliberately pin the
**English-only invariant itself** (`deepEqual(shipped, ["en"])`). Without that
pin those sweeps are vacuous by construction — the drift loop never executes on a
single-locale tree, so they would stay green even if the English catalog were
emptied. Adding a locale must be a visible, deliberate change that re-arms them.

## What was removed

Deleted with the English-only move — do not reintroduce without also restoring
the gates that made them safe:

- `docs/i18n/` — 1,248 files / ~55 MB of translated docs, plus every
  `🌐 Languages:` link bar that pointed into it.
- `bin/cli/locales/*.json` except `en.json` (42 catalogs), and
  `bin/cli/scripts/generate-locales.mjs`.
- Translation/generation tooling: `run-translation.mjs`, `generate-multilang.mjs`,
  `i18n_autotranslate.py`, `check_translations.py`, `validate_translation.py`,
  `untranslatable-keys.json`, `apply-priority-overrides.mjs`,
  `translate-endpoint-tier-keys.mjs`, `fill-missing-from-en.mjs`,
  `merge-keys.mjs`, `build-pending-from-missing.mjs`,
  `extract-keys-from-diff.mjs`, `sync-llm-mirrors.mjs`,
  `audit-dashboard-pages.mjs`, `generate-qa-checklist.mjs`, `run-visual-qa.mjs`.
- Glossary gates: `check-glossary-consistency.mjs`, `glossary-normalize.mjs`,
  `scripts/i18n/glossary/` (zh-CN, zh-TW, ko, protected-terms), and the
  `i18n Glossary (zh-CN, ko)` CI job — whose steps had been hard-failing with
  `ENOENT` since the locale catalogs were dropped.
- `check-translation-drift.mjs` (tracked the deleted `docs/i18n` mirrors) and the
  `i18n Validation (all languages)` CI job (looped over non-`en` catalogs, of
  which there are none).
- CHANGELOG mirror plumbing: `scripts/release/sync-changelog-i18n.mjs` and the
  mirror-resync block in `scripts/release/sync-next-cycle.mjs`.
- `LanguageSelector.tsx` and the i18n mirror validation in
  `scripts/check/check-docs-sync.mjs`.

`npm run` no longer defines `i18n:run`, `i18n:run:dry`, `i18n:check`,
`i18n:check-glossary`, `i18n:check-glossary:ko` or `release:sync-changelog-i18n`.

## Adding a locale

Deliberately not a one-command operation any more. In rough order:

1. Add the entry to `config/i18n.json` (`code`, `label`, `name`, `native`,
   `english`, `flag`; add to `rtl` if applicable).
2. Add `src/i18n/messages/<code>.json`. `npm run i18n:sync-ui` will scaffold it
   from English with `__MISSING__:` sentinels.
3. Restore locale negotiation in `src/i18n/request.ts` — read `LOCALE_COOKIE`,
   validate against `LOCALES`, and merge the locale catalog over English with
   `deepMergeFallback` (still exported for exactly this). Note that the
   module-scope memoization only holds for a single catalog: re-introduce a
   per-locale cache rather than dropping back to per-request normalization.
4. Restore `dir` handling in `src/app/layout.tsx` if the locale is RTL, and a
   language switcher if users need to choose.
5. Add `bin/cli/locales/<code>.json` and restore the fallback chain in
   `bin/cli/i18n.mjs` (`normalize()` must re-validate locale codes against
   `/^[a-zA-Z0-9-]+$/` before touching the filesystem).
6. Update the invariant assertions in `scripts/check/check-cli-i18n.mjs` and
   `tests/unit/i18n-placeholder-parity.test.ts` — they pin `["en"]` on purpose and
   will fail until you widen them intentionally.

## Translator backend env vars

`scripts/i18n/sync-ui-keys.mjs` can call an OpenAI-compatible endpoint to fill
`__MISSING__:` placeholders. All five variables are unset by default; see
[ENVIRONMENT.md](../reference/ENVIRONMENT.md) for the full table.

| Variable                            | Default   |
| ----------------------------------- | --------- |
| `OMNIROUTE_TRANSLATION_API_URL`     | _(unset)_ |
| `OMNIROUTE_TRANSLATION_API_KEY`     | _(unset)_ |
| `OMNIROUTE_TRANSLATION_MODEL`       | _(unset)_ |
| `OMNIROUTE_TRANSLATION_TIMEOUT_MS`  | `60000`   |
| `OMNIROUTE_TRANSLATION_CONCURRENCY` | `4`       |
